## Setting up the environment

### With Rye

We use [Rye](https://rye.astral.sh/) to manage dependencies because it will automatically provision a Python environment with the expected Python version (see `.python-version`). To set it up, run:

```sh
$ ./scripts/bootstrap
```

Or [install Rye manually](https://rye.astral.sh/guide/installation/) and run:

```sh
$ rye sync --all-features
```

You can then run scripts using `rye run python script.py` or by activating the virtual environment:

```sh
# Activate the virtual environment - https://docs.python.org/3/library/venv.html#how-venvs-work
$ source .venv/bin/activate

# now you can omit the `rye run` prefix
$ python script.py
```

### Without Rye

Alternatively if you don't want to install `Rye`, you can stick with the standard `pip` setup by ensuring you have the Python version specified in `.python-version`, create a virtual environment however you desire and then install dependencies using this command:

```sh
$ pip install -r requirements-dev.lock
```

## How this SDK is built

The SDK surface is **fully generated** from two files vendored from the platform monorepo:

- `spec/openapi.yaml` — the public OpenAPI spec (source of truth)
- `spec/sdk-manifest.yaml` — maps each operation to its SDK name (shared with the
  [TypeScript SDK](https://github.com/anchorbrowser/AnchorBrowser-SDK-Typescript); camelCase manifest
  names become snake_case here: `class: Sessions, method: createSession` → `client.sessions.create_session`)

`./scripts/generate` runs the whole chain:

1. `scripts/preprocess_spec.py` — hoists inline response schemas into named components
   (`Sessions.getSession` → `SessionsGetSessionResponse`) so every operation returns a typed model
2. [datamodel-code-generator](https://github.com/koxudaxi/datamodel-code-generator) — writes
   `src/anchorbrowser/types/models.py` (pydantic response models) and `types/params.py` (request TypedDicts)
3. `scripts/generate_resources.py` — writes one resource file per manifest class under
   `src/anchorbrowser/resources/` plus the client mixins, in the style of the vendored runtime
4. `ruff format` over everything it wrote

Generated files carry a `# Generated by scripts/generate …` header — never edit them by hand; edit the
spec/manifest (in the monorepo) or the generator scripts instead. Hand-written files the generator never
touches: `resources/browser.py`, `resources/agent_helpers.py`, `lib/`, and the runtime
(`_base_client.py`, `_models.py`, …).

To add or rename an operation: update `docs/openapi.yaml` + `docs/sdk-manifest.yaml` in the monorepo,
re-vendor them into `spec/`, then run `./scripts/generate`. CI (`./scripts/generate --check`) fails if
generated code is out of sync with the spec, and the spec-coverage test fails on any operation without a
manifest naming entry.

## Modifying/Adding code

Runtime behavior (auth, retries, errors, serialization) lives in the hand-written runtime modules and can
be edited directly. Anything under `src/anchorbrowser/types/` or a file with the generated header will be
overwritten by the next `./scripts/generate` run.

## Using the repository from source

See [LOCAL_TESTING.md](LOCAL_TESTING.md) — `./scripts/pack-local` builds the exact publishable wheel for
installing in another project. Alternatively install straight from git:

```sh
$ pip install git+ssh://git@github.com/anchorbrowser/AnchorBrowser-SDK-Python.git
```

## Running tests & checks

```sh
$ ./scripts/lint              # ruff + pyright + mypy + import check
$ ./scripts/generate --check  # generated code matches spec/ (what CI runs)
$ ./scripts/test              # unit + spec-coverage + wire-parity suites
```

The wire-parity suite invokes every operation against a local capture server and compares the exact HTTP
request to `tests/spec_suite/wire_parity_golden.json`. After an *intentional* wire change, regenerate the
golden and review the diff — it is the reviewable record of the change:

```sh
$ ./scripts/update-wire-golden
```

## Linting and formatting

This repository uses [ruff](https://github.com/astral-sh/ruff) for linting/formatting and
pyright + mypy for type checking.

To lint:

```sh
$ ./scripts/lint
```

To format and fix all ruff issues automatically:

```sh
$ ./scripts/format
```

## Publishing and releases

Releases are cut with [the `Release` GitHub action](https://www.github.com/anchorbrowser/AnchorBrowser-SDK-Python/actions/workflows/release.yml):
run it with the new version (PEP 440, e.g. `1.2.0` or `1.2.0rc1`) as input. It runs the full quality gate,
bumps the version, updates the changelog, tags, creates a GitHub release, and publishes to PyPI via OIDC
trusted publishing (dispatched to [`publish-pypi.yml`](.github/workflows/publish-pypi.yml) — no API token
involved).

To re-publish after a failed publish step, re-run the `Publish PyPI` workflow manually from the Actions tab.
